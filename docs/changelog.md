- Answer-slot gate in `scripts/ingest/validate.ts`: a slot naming no question would render a blank nobody can fill, and a question with two slots would give it two boxes whose state disagrees. Both are invisible in the browser
- Typeable-answer gate in `scripts/ingest/validate.ts`: an `exact` typed answer whose key and every accepted variant need a non-ASCII letter fails the build. Grading forgives accents but not distinct letters, so a key of `þu` with no `thu` variant is unanswerable however well it is solved
- **A consensus ingest pipeline, replacing human review as the publish gate.** `scripts/ingest/manifest.ts` (`bdfb674`) pins page spans, official points, and author bylines straight off each booklet's `pdftotext` output, so the model never owns a fact machine-readable text already states — covers every target year (2016-2022) except 2019, whose booklets are mojibake and fall back to model values for these fields alone. `draft.ts` now drafts every problem twice (`3b86222`): pass A at 150dpi, reading every table cell by cell; pass B at 300dpi, reading each page holistically first. Two passes that fail differently is the point — a misreading only one of them makes is what the rest of the pipeline exists to catch
- `scripts/ingest/diff.ts` (`ad04809`, `26b7d30`, `b6d55fc`, `1049447`): compares the two drafts on fact only — answer keys, grading modes, points, choices, figure counts. Hints, explanations, invented `acceptedVariants`, and per-question `points` are excluded on purpose; see Fixed, below, for why
- `scripts/ingest/witness.ts` (`a893eb2`): checks the two passes' language data against the booklet's own text layer, which can't repeat a misreading the way a second model pass can — this is the check that would have caught three of the five transcription errors found by hand in the 2023 review batch. Skipped for 2019, whose booklets return a substitution cipher instead of readable text
- `scripts/ingest/arbitrate.ts` (`548a560`, `b1afe6e`): one model call per disagreement, given the page image and the extracted text, that either picks a value or answers UNRESOLVED — defaulting to UNRESOLVED is correct, since an unresolved flag only parks the problem, while a confidently wrong pick reaches a student. Never run for 2019, which has no independent evidence to arbitrate with, and 2019 is never auto-published at all regardless of what its two passes agree on (`7781e8a`): agreement between two model passes can't catch a correlated misread, and the witness check that would is exactly what 2019 lacks
- `scripts/ingest/figures.ts` (`ceb01b3`, `687ab56`, `65f83be`, `f0bcfdf`): crops figures automatically instead of by hand. The model gives a coarse percentage box, a confirm pass checks whether the cut is complete or clipped, and the box widens and retries up to three times before the problem parks
- `scripts/ingest/fonts.ts` (`020d8c8`, `72bc167`): fetches a Noto subset from the Google Fonts CSS API for any script the corpus introduces that the shipped fonts don't already cover
- `scripts/ingest/publish.ts` (`072c459`, `e8b6da2`): decides, writes, and reports. A record publishes only when it has zero flags and parses clean; everything else writes to `content/parked/<id>.json` with a `_parkReasons` array. `content/parked/` is committed on purpose — it's the queue for later human passes and is meant to be read in a diff; `lib/content.ts` reads neither it nor `content/drafts/`
- `scripts/ingest/run.ts` (`2456934`, `e8951fe`): orchestrates all seven stages for one or more years, four problems at a time, resuming from existing drafts so an interrupted run doesn't pay twice. `npm run ingest -- <year...> | --all | --dry`
- `docs/ingest-runs/*.md`: a dated report written by every run, naming every parked problem and the reasons it parked
- `tests/ingest/*.test.ts`: unit coverage for manifest, diff, witness, arbitrate, figures, fonts, pool, and publish

- **Dark mode**, as a second theme rather than an inversion of the first. `app/globals.css` now declares every colour once as `light-dark(day, night)`, switched by the CSS `color-scheme` property — so the site follows the reader's machine with no JavaScript, and `color-scheme` also repaints the browser's own furniture (scrollbars, form controls, the overscroll gutter) to match. Night ratios were solved against the night ground rather than mirrored from the day column, because equal WCAG contrast reads as less separation near black: hairlines, tonal blocks and the lifted surface each take a wider step at night. 21 pairings verified before shipping, all passing
- `--surface`, the White Means Above rule made a token. `#ffffff` was a literal in fourteen components and is the one value that could not survive a theme — white does not mean "raised" on a dark page, it means "hole". The token means one step lifted off the ground, and it lifts in both themes
- `--on-action`, the label that sits on an action fill. `text-ink` on the call to action was correct only while `--ink` was guaranteed dark; the orange is light in both themes, so its label is dark in both (6.18:1 day, 6.24:1 night)
- `--select` (selection highlight, previously the system blue), and `--lift-popover-tone` / `--lift-plate-tone`, which keep the two shadow recipes' geometry and change only their colour
- `lib/theme.ts`: localStorage override on the same `useSyncExternalStore` pattern as `lib/progress.ts`, plus a `matchMedia` listener so a machine that flips at sunset takes an untouched page with it. `getServerSnapshot` returns `null` so the statically generated HTML cannot mismatch on hydration
- `components/theme-toggle.tsx`: two cells borrowed from the filter-chip vocabulary, active cell taking the ink fill. Which cell is filled is decided in CSS, not React, so it is correct on the first frame of a statically generated page; JavaScript only supplies `aria-pressed`. Placed on the row that already holds the back link, so no navigation chrome is invented
- Blocking inline script in `app/layout.tsx` (~200 bytes) applying a stored override before first paint — verified in the served HTML to sit inside `<head>`, after the stylesheet link, before `<body>`, with no `defer`/`async`
- `public/how/*-dark.png`: dark captures of the three landing-page screenshots, each taken from the same scroll position as its light twin with the clock frozen at 13:56, so only the theme differs. Rendered as a CSS-swapped pair rather than a `<picture>` media query, which can only read the machine's setting and would keep serving the light shot to a reader who chose dark by hand. The hidden twin is `display:none`, so a lazy image never fetches it

### Changed

- The wordmark is both brand colours instead of one plus black: `morph` in NACLO cyan, `eme` in NACLO orange, split at the same morpheme boundary as before. WCAG 1.4.3 exempts text that is part of a logo, which is what lets the cyan run at 2.63:1 here and nowhere else on the site
- The primary button is orange-filled with a 2px cyan border, and its hover wipe sweeps in cyan rather than ink. It also dropped to a single label: the wipe carried a stacked copy because paper on the orange is 2.13:1 and ink on it 9.88:1, so no one label could cross the transition readable. Both fills take the same black label now, 9.88:1 on the orange and 7.98:1 on the cyan, so the duplicate went with the ink
- **The palette is now NACLO's own.** Both chromatic brand roles were rebased onto the competition's actual colours, taken from naclo.org rather than interpreted from it: `#ff9a04` is declared on every heading in their stylesheet and is the literal value of 3,634 pixels of their logo artwork, and `#00aaee` is declared eight times in the same file, filling the nav bar and setting every link. The orange replaces `oklch(0.7 0.19 45)` = `#fa6e1d` — a yellower, lighter hue at `oklch(0.774 0.173 64.9)`. Cyan replaces verdigris `#2f6b4f`/`#61a482` as the colour of a correct answer. `#44ccf4`, NACLO's own nav hover, is the dark column's cyan
- **The ground is NACLO's too.** `--paper` went `#fbfaf7` → `#ffffff` and `--ink` `#16181d` → `#000000`, and the dark column was de-warmed to match (`#191712` → `#141414`, `#eae7e0` → `#e8e8e8`). The warm paper stock was the better reading ground and was given up knowingly: a palette that borrows a brand's two hues while keeping its own paper is not that brand's palette. Two themes in different temperatures would have been two design systems
- Oxblood stays, by explicit decision, as the one chromatic role that is not NACLO's. Red for a wrong answer is near-universal, the brand offers no substitute, and the alternative was spending orange on both "press this" and "you got this wrong"
- **The Lifted Surface Rule changed instrument, not meaning.** Nothing sits above `#ffffff`, so by day `--surface` now equals `--paper` and lift is carried by the border and shadow already drawn around every table, input, popover and unselected chip. Night still lifts (`#1f1f1f` over `#141414`), because there the step exists. Anything relying on `--surface` alone for separation must now carry a border
- Four `text-good` usages moved to `text-good-deep` (`inline-answer`, `concept-filter`, `question-row`, `home-demo`). Neither brand hue can set text on white — the orange is 2.13:1 there and the cyan 2.63:1 — so each now keeps a deepened twin that can, exactly the arrangement `--action`/`--action-deep` already had. The vivid values fill, outline and underline; the deep values write. naclo.org sets links in `#00aaee` directly, which is a real failure on their page and was not copied
- Day-column accessibility improved as a side effect of leaving warm paper: `--ink-faint` 3.09:1 → 4.54:1 and `--rule-strong` 1.65:1 → 3.03:1, both of which had been below their WCAG floors. The night column gained the same two fixes (3.56:1 → 4.54:1 and 1.95:1 → 3.02:1)
- `--on-action` is now `#000000` rather than the warm near-black, and is joined by `--on-good`. Both brand hues are light in both themes, so both carry a black label in both: 9.88:1 on the orange, 7.98:1 on the cyan
- `--select` moved off the warm orange wash to a pale cyan (`#a5ddf5` day, `#0e4a63` night), and the two shadow tones to true black now that `--ink` no longer supplies a warm one
- `app/icon.svg` moved from `#16181d`/`#fbfaf7` to `#000000`/`#ffffff`, keeping the reversed lockup
- **Correction to an earlier entry below:** `--action` was recorded as clearing "5.03:1 on paper". The real figure for `#fa6e1d` on `#fbfaf7` is 2.75:1; 6.93:1 was `--action-deep`, and the two were conflated. The new orange is 2.13:1 on white, which is accepted for the same reason the old value was: a filled control is identified by its 9.88:1 black label, so WCAG 1.4.11 does not ask the boundary to carry it, and the wordmark is exempt under 1.4.3


- Problem figures are matted rather than filtered in dark mode. `filter: invert()` is the standard move for diagrams and is a **content bug** here: 2016 G turns on which monk's robe is white and which is black, so inverting it does not dim the figure, it changes the answer. Photographs, engravings and line art share `content/assets/` with nothing marking them apart, so no filter is safe across the set. Figures keep their true tone on a light mat with a rule around it, which frames the brightness as intentional — the plate metaphor the rest of the system borrows from printing, made literal
- The three landing-page screenshots were recaptured in both themes rather than only in dark, so the pair cannot reframe under a reader who flips the toggle mid-look
- `--action` deliberately does not move between themes. It is the brand, it is legible on both grounds (5.03:1 on paper, 6.24:1 on charcoal), and moving it would make the wordmark two different oranges. Its two derived values do move, in opposite directions: `--action-deep` means "the action colour safe at body size", which is darker than the fill by day and lighter than it by night

- **Human review moved off the publish path.** A record now publishes when the consensus pipeline's checks clear, not when a person signs off; review is a follow-on pass over `content/parked/` and over answers a student flags as wrong. The site's own claim about this changed to match: `app/page.tsx`'s guarantee under the CTA no longer says a person checks every problem before it ships, and now says what actually happens — two independent transcriptions, compared against each other and against the text inside the original PDF, with any answer flaggable as wrong. An earlier draft of that sentence claimed the problems were cross-checked against NACLO's official solutions, which the final review caught as an over-claim: the solution pages are an input to drafting, never a check, and arbitration is only ever shown the problem pages. `CLAUDE.md`'s content-integrity rules, `PRODUCT.md`'s process description, and `docs/architecture.md`'s ingest data flow were all reconciled to the same reality
- `CLAUDE.md`'s architecture tree also had drifted independently of the pipeline work: it was missing several components (`coming-soon.tsx`, `home-demo.tsx`, `inline-answer.tsx`, `use-answer.ts`) and `content/parked/`, and its `scripts/ingest/` listing still named the four original files rather than the pipeline's real modules
- Arbitration cap lowered from 25 flags to 5 (`4a2244f`). The first run put sixteen flags through arbitration and every one returned UNRESOLVED, which is the arbitration prompt behaving as designed, not a reason to keep paying per-flag for an answer that never comes

- Dropped the difficulty filter from `/practice`. Concept is the axis that answers "what do I want to work on"; difficulty was a second axis nobody asked for, and it narrowed a 30-problem library to slices of five
- Retired the concept colour ring. Eight coded dots across a library page read as decoration rather than wayfinding, which is the opposite of what colour is for here. Concepts are named in words and the words were always doing the work. `lib/concept-color.ts` and the `--c-*` tokens are gone
- Action colour is warm now (`oklch(0.46 0.12 62)`, a burnt amber) rather than the cool blue-violet that reads as a generated default. 7.02:1 on paper, and it runs darker and far less red than oxblood, which it never shares a role with: one fills a button, the other is small text beside a wrong answer


- Home page leads with a real problem. `components/home-demo.tsx` puts three verbatim rows of 2023 D (Permyak, Pavel Iosad) and its question (b) on the landing page, graded by the same `checkExact` the site uses, so a visitor solves a genuine NACLO blank before committing to anything. Writes no progress: a demonstration should not mark a problem nobody opened
- Primary action moved above the explainer. Measured on a 390px viewport: the CTA was at 896px against an 844px fold and is now at 744px, fully visible without scrolling
- Opening copy leads with the puzzle rather than the contest, since PRODUCT.md commits to an audience that has never heard of NACLO. The "drafted with AI, checked by a person" line moved out of the second sentence to sit under the CTA as a guarantee rather than a process disclosure


- **A colour system with four roles.** `--accent` (deep azure, `oklch(0.42 0.115 250)`) for action and brand: the primary button, a selected control, the `-eme` of the wordmark. A ring of eight hues, one per concept tag, for subject: dots beside the tag name in the practice list, the coverage list and the problem header, and the fill of a selected filter chip. Oxblood and verdigris keep cost/error and correct. Nothing else is chromatic, and there are no gradients, tinted cards, or coloured surfaces

### Notes

- Grading-mode split holds as the library grows: `npm run validate` now reports 232 sub-questions across 64 records, 218 `exact` / 14 `llm` / 0 `self` (94%), still past the spec's 80% "AI grading is nearly optional" threshold. 14 problems are playable, 50 are catalogue entries.
- Correct is not always right. 2024 A's medieval shorthand has two 9-shaped signs, and `ꝯ` U+A76F is genuinely the character for the baseline one — but that problem's symbol bank lists it as entry 21 typed as a plain digit, and its answers are sequences of bank numbers, so the shape in the word has to match the shape in the bank. The PDF's own notation wins over the palaeographically proper character.
- A `unicode-range` is a promise the font has to keep. Widening a range to cover a character the woff2 does not contain passes validation and still renders a box, which is strictly worse than failing the build — no font we ship carries U+2192, so drafts are told to write "gives" instead of reaching for an arrow. New subsets are verified against the file's cmap, not just declared.
- The spec's open question is answered: `npm run validate` reports 98 of 106 sub-questions (92%) grade `exact`, past the spec's 80% "AI grading is nearly optional" threshold. The other 8 are `llm`, all in problem F (Māori sentence translation); zero `self`. `/api/grade` currently serves only that one problem's worth of questions.
- `npm audit`: 12 high-severity advisories. 9 trace through the ESLint toolchain (`brace-expansion`/`minimatch`), devDependencies only, never shipped. The other 3 (`postcss`, `sharp`, `next` itself) are nested under `next`, a production dependency — `sharp` is next's optional image-optimization dep, `postcss` is next's own internal copy (build-time only). `npm audit fix --force` is the only fix path offered, and it proposes downgrading to `next@9.3.3`, which is not viable. Deliberately left; worth a closer look since it touches a prod dependency, not just dev tooling.
- Request-time AI help (`/api/help`) is a deliberate departure from `docs/project_spec.md`, which says hints and explanations are written offline because "a model holding the full solution tends to give too much away." The reviewed written ladder stays the default and is cheaper in XP; AI help is an addition for what the written ladder can't cover. The spec's four reasons for offline content still hold for the written ladder itself. `CLAUDE.md`'s "Hints and explanations are written at ingest, never generated at request time" line is now stale against this and needs reconciling, same as the `app/exam/` staleness fixed this round.
- `reveal` mode is also how `llm`-graded answers can be shown without shipping them in the client bundle: the 8 Māori answer keys are verifiably absent from the static HTML and arrive only when a student asks for them.
- Dark mode is the first thing in this project to make `--ink` and `--paper` prove they were semantic and not just descriptive. They mean "the foreground, and the fill that marks a control active" and "the page ground" — so every `bg-ink text-paper` pair in the codebase (primary button, selected chip, open Hint trigger) kept working correctly with only its values swapped, and not one of those components was touched. The two tokens that did need work, `bg-white` and `text-ink`-on-orange, were the two that were literal rather than semantic.
- `--ink-faint` fails WCAG AA at 3.56:1 on the night ground and 3.08:1 on a night surface — and fails identically in light mode at 3.09:1 and 3.23:1, on the same nine strings. Verified by walking the live DOM in both themes and computing every text node against its effective background. Pre-existing, not a dark-mode regression, and deliberately left rather than changing the light theme unasked. Some of the affected strings are real instructions rather than metadata ("Each number goes with the circle it touches...", "Hints never give the answer"), so lifting the token in both themes is worth a decision.
- Verified `light-dark()` survives inside Tailwind v4's `color-mix()` opacity modifiers before committing to it (`bg-tint/50` computes to `oklab(... / 0.5)`). Had it not, the single-source palette would have had to become two duplicated blocks.
